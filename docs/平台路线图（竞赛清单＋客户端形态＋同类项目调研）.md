# 平台路线图：还能接哪些竞赛 · 要不要网页/桌面端 · GitHub 上有没有同类

> 调研日期：2026-09-30 ｜ 数据来源：教育部认可竞赛清单（84 项，附源）、GitHub 官方搜索/API 实测、公开项目元数据
> 结论先行：**竞赛可接的很多（我们按"数据可获得性 + 骨架契合度"分了三档）；客户端现在只有 CLI，建议先做网页端、桌面端走 DSH 插件最省；GitHub 上"AI 竞赛助手"只有单竞赛单点尝试，多竞赛平台这个位置目前是空的。**

---

## 一、还能接哪些竞赛（基于教育部认可的 84 项清单）

清单来源：[2025 年教育部认可的全国大学生学科竞赛目录清单（湖南工学院转发）](https://www.hnit.edu.cn/cxcyxy/info/1039/4945.htm)，原始榜单来自中国高等教育学会《全国普通高校大学生竞赛分析报告》。全量 84 项已存为 `data/竞赛清单-教育部认可84项.txt`。

**筛选判据**（三条同时满足才进第一档）：
① 任务以"**信息处理 + 方案设计 + 报告/论文**"为主（而不是现场手技）；② **赛题/规则公开可得**（能建题库）；③ 关键环节**可被工具化**（能做出确定性工具，而不是只能聊天）。

### 🥉 第三档：明确**不做**（AI 助手边际价值低或数据不可得）

医学技术技能(7)、金相技能(32)、地质技能(29)、测绘(67)、生命科学(44)、物理实验(45)、化学实验(62)/化工实验(61)、水利创新(60)、花园设计建造(64)、外语演讲/辩论/跨文化/诵读(15/53/56/57)、财会税务(72/78)、企业模拟与沙盘(73/74)、世界技能大赛及其选拔(81/82)。
**理由**：考的是**现场操作/专业技能/主观评审**，或以**封闭题库+官方判分**为主，我们既拿不到数据也帮不上关键环节 —— 与其铺开，不如把第一档做深。

> ★ 建议接入顺序（按"复用度 ÷ 工作量"）：**智能汽车（最快，调参直接复用）→ 数学建模（需求已被验证，但要差异化）→ 嵌入式（固件工作台）→ 计设/人工智能创意赛 → 机器人类**。

## 二、要不要网页端 / 桌面端

**现状：只有 CLI（命令行）。** 这是当前最大的短板 —— 队友用不了、面试官看不到、手机更打不开。

| 形态 | 现状 | 工作量 | 优点 | 缺点 | 建议 |
|---|---|---|---|---|---|
| **CLI** | ✅ 已有 | — | 零成本、可脚本化、适合自己用 | 队友不会装 Python | 保留 |
| **网页端**（FastAPI + 原生 HTML/JS） | ❌ | **2–3 天** | 队友**零安装**；能发链接/截图；手机也能开；可上传数据直接看曲线 | 要起服务（本机 uvicorn 即可） | ★★ **先做** |
| **DSH 插件薄壳** | ❌ | **1–2 天** | **白捡一个桌面端**：宿主已有窗口/设置页/权限体系，零打包零更新 | 绑在 DSH 生态里 | ★★ 想要"桌面端"就走这条 |
| 桌面端（Tauri / Electron 打包） | ❌ | 4–7 天 | 双击即用、像正经软件 | 打包/签名/自动更新都要维护，收益低 | ⏸ 后置 |
| 手机端 | ❌ | 响应式 **0.5 天** / 小程序 5 天+ | 赛场用手机看报告 | 小程序要主体与审核 | 先做**响应式网页**（顺带就是手机端） |

### 网页端技术方案（可直接开工）

```
FastAPI（复用现有 Python 逻辑，不重写）
├── POST /api/analyze        分析赛题（SSE 流式推送"第 N 步 / 调用了什么工具"）
├── POST /api/tune           上传 CSV/串口日志 → 指标表 + 曲线 PNG + 调参报告
├── GET  /api/reports        列出 out/ 里的报告
└── GET  /api/report/{name}  下载 md / docx / png
前端：单页 HTML + 原生 JS（零构建、零前端框架），表格与 Markdown 直接渲染
```

- 需要的改造很小：把 `loop.py` 的 `_log` 从 print 改成**可注入回调**，网页端就能实时看到 Agent 在干什么（这一步值得做，体验差别很大）。
- **验收标准**：队友在浏览器里上传一段串口数据 → **30 秒内**看到指标表 + 曲线 + 可下载 Word 报告，**全程不装任何东西**。

### 结论（我们的位置）

1. **"AI 竞赛助手"目前只有单竞赛、单点的尝试**（电赛→MSPM0 skill ★372；数模→skills ★1058），**没有多竞赛平台** → ★ **我们要做的位置是空的**（这正是 [DSH插件空白地图](../dsh-ecosystem/DSH插件空白地图.md) 同款方法论：先搜现成的，搜不到就是机会）。
2. 我们的三个差异点：
   - **多竞赛分区**：一套骨架（Agent Loop + 工具）服务多个竞赛，加分区不动核心代码；
   - **确定性工具 + 可验证**：调参指标由 numpy 计算并**用解析解校验**（σ% 16.31 vs 解析 16.30），别人多是纯 prompt 靠模型"估"；
   - **中文竞赛垂直深度**：评分标准（20/50/50+综合测评 30）、历年规律、2027 选题预测、赛区答疑检索 —— 这些别人都没做。
3. **风险提示**：数模 skills ★1058 说明"竞赛 + Agent Skills"这条路**需求被验证过、也有人做得不错** → 我们接数模分区时**不能只是再写一份 skill**，必须把"**数据工具 + 论文产物闭环**"打通才有差异。

## 四、下一步建议（按优先级）

| 优先级 | 做什么 | 为什么 | 工作量 |
|---|---|---|---|
| **1** | **网页端**（FastAPI + 原生前端 + SSE 实时进度） | 现在只有 CLI，队友/面试官都用不上 —— 这是当前最大瓶颈 | 2–3 天 |
| **2** | **DSH 插件薄壳** | 顺手拿到"桌面端"，几乎零打包成本；还能进插件市场被人看见 | 1–2 天 |
| **3** | **接入第二个竞赛分区：智能汽车竞赛** | 验证"平台化"是否真成立；调参助手直接复用，题库小 | 0.5–1 天 |
| 4 | 数学建模分区（含数据处理/优化/统计工具 + 论文闭环） | 需求已被验证，但要做差异化 | 3–5 天 |
| 5 | v0.3 评测框架（真题自动打分 + 回归） | 对求职（Agent 评测岗）最对口 | 2–3 天 |
