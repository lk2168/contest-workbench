## 修复：首页打不开（v0.5.0 的 exe 有这个 bug）

**症状**：打开首页只看到一条红色提示——
`加载失败：Cannot set properties of null (setting 'textContent')`，
统计条和"竞赛分区"里的电赛卡片都不显示。

**原因**：上一版把设置抽屉改版时，删掉了 `#modelName` / `#keySource` 两个元素，
但首屏初始化函数 `init()` 里还在给它们赋值 → 抛异常 → **整个初始化中断**。
（`#modelName` / `#keySource` 的功能已经由设置抽屉里的 `#modelSel` / `#keyStatus` / `#paths` 接手。）

**为什么测试没抓到**：当时四套测试里，前端相关的只断言**静态 HTML 字符串**，
**从不执行 JS** —— 这类"运行时才炸"的错误完全在盲区里。是你打开首页才发现的。

### 这一版补上了「前端运行时测试」

新增 `tests/test_frontend_runtime.py`：用**无头浏览器真渲染一遍首页**，然后断言渲染结果
（没有"加载失败"错误条、统计条已填充、分区卡片已渲染、没有 JS 报错字样）。

- 没有浏览器的环境（比如 ubuntu CI）会**自动跳过**，不算失败；windows runner 自带 Edge，会真的执行
- 并且**验证过这个测试真的有效**：把 bug 注入回去，它立刻变红并复现原始报错；恢复后 6/6 通过

> 顺手修了测试自身的一个坑：`--dump-dom` 会把内联 `<script>` 的**源码**也输出，
> 直接在整段 DOM 里搜索会匹配到 JS 模板字符串与注释（假通过）。现在先剔掉脚本/样式再断言。

## 修复：找不到题库（用户报的第二个问题）

**症状**：打开后「年份/批次」下拉是空的，题目显示"（该批次没有题目）"。

**原因**：打包后的程序只在**自己旁边**找题库（`exe所在目录/data/题库/`），
而题库其实在上层目录；更要紧的是 —— **下载 exe 的人根本不知道该往哪放**。

**改法**：

1. **多位置自动搜索**（按优先级）：
   - `~/.contest-workbench/题库/<分区>/` ← ★ 推荐（下载 exe 的人放这里）
   - `exe 同目录/data/题库/<分区>/`
   - `exe 上一层/data/题库/<分区>/` ← 我们的开发布局正好命中
   - 当前工作目录 `data/题库/<分区>/`
2. **界面上直接把"该放哪"讲清楚**：题库为空时，赛题分析页会多出一块引导面板，
   列出**按优先级搜索过的所有路径**，并给出目录结构示例。
3. **一键打开题库目录**：点「打开题库目录（放文件进去）」会在文件管理器里打开推荐位置
   （不存在就自动创建），放好文件点「放好了，重新扫描」即可 —— 不需要碰命令行。
4. 顺带加了「打开输出目录」。

**实测**（打包产物）：原生窗口标题「大学生竞赛工作台」、服务 `frozen=True`、自检 8/8、
**题库找到 40 道题 / 5 个年份**（通过"exe 上一层"这条候选路径命中）。

## 怎么用

下载 `contest-workbench.exe`，**双击**即可（Windows，**不需要装 Python**）。

1. 双击 exe（首次启动要解包 46 MB，约 **5–10 秒**，属正常）
2. 浏览器打开后点右上角「**设置**」→ 粘贴 **DeepSeek API Key** → 保存 → 点「**测试连接**」
   （Key 只存在你自己电脑上）
3. 首页点「进入电赛」→ 选年份和题目 → 点「**开始分析**」

出问题先点设置里的「**运行自检**」，它会逐项告诉你哪里不对。
