chore: 补齐开源项目配套（贡献指南 / Issue 模板 / PR 模板 / 引用 / CI）

用户要求把项目做成「不懂 AI 的同学也能参与」的正经开源项目，本次补齐 5 项：

1. CONTRIBUTING.md：按「不需要编程 → 需要编程」排序列出可参与方式
   （许愿分区 / 报 bug / 提供题库线索 / 改文档 / 接新分区 / 加工具），
   含本地跑起来、接新分区三件事、提 PR 前必跑的三套测试、6 条硬约定
   （中文、可验证优先、零构建、不许编造、一次一件事、不提交版权内容）
2. .github/ISSUE_TEMPLATE/：报 Bug（含版本/系统/复现步骤/确认没贴 Key）、
   分区许愿（考什么 / 公开资料链接 / 需要什么工具）、题库反馈（明确禁止粘贴赛题原文）、
   config.yml 引导到 Discussions 与版权说明
3. .github/PULL_REQUEST_TEMPLATE.md：检查清单化（测试跑过、没破坏零构建、
   没提交版权内容/密钥/本机路径、文案中文、不确定的标待确认）
4. CITATION.cff：规范引用信息（含「赛题原文不在开源范围」的说明）
5. .github/workflows/tests.yml：矩阵 CI（ubuntu 3.10/3.13 + windows 3.13）
   跑三套离线测试 + cli 自检；README 加 CI 徽章

关键前提修复：题库因版权不进仓库，CI 上必然没有题库 —— 原来
test_offline.py / test_web.py 里依赖题库的断言会直接失败（CI 徽章永远是红的）。
现在两套测试都支持 needs_kb 语义：没题库时「跳过」而不是「失败」，
本地建好题库后自动变回严格断言；并修掉 test_web.py 里用 next() 取 H 题
在题库为空时会抛 StopIteration 让整套测试崩掉的隐患。

测试：本地 27+20+48 全过；模拟 CI（切到无题库分区）23+43 通过、0 失败、跳过 4/5 项。
