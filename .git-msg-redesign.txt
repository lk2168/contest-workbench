redesign(web): 界面重做（Swiss 设计锚点）+ 信息架构分层，技术参数移入设置

用户反馈：①「最多步数」这种参数没有任何 AI 接触的人看不懂 → 移入设置、小白第一眼看不到
② 调参助手只有电赛用得上 → 移到二级页面，选到电赛才出现
③ 界面要更简洁；④ 去 GitHub 上找现成的高星设计

先找现成的（按项目规矩）：
- 采用 Ilm-Alan/frontend-design（★127，Agent Skill，8 套设计锚点 + 内容纪律），已装到工作区 .dsh/skills/
- 评估后不用 water.css（★8651，通用默认风）与 daisyui（★42510）/ shadcn（★20587，需构建链会破坏"零安装"）

设计：Swiss 锚点
- 纯白/浅灰底、单一强调色克莱因蓝 #002FA7、1px 细线代替阴影与圆角、左对齐、tabular-nums
- 差异动作：题面与进度双栏 + 一条 1px 竖线贯穿；Agent 每步用 01/02/03 两位列号
- 内容纪律：界面零 emoji（原日志里的工具/结果图标全删）、文案只用真实信息

信息架构（三层）
- 首屏 = 选择竞赛（4 张分区卡片，零技术参数）
- 二级页 = 分区工作台（面包屑「← 全部竞赛」）：赛题分析 / 调参助手 / 成果库
- 设置（右上角按钮，默认 hidden）= 最多步数、模型、只看提示词、API Key 来源

后端：
- /api/domains 增加 capabilities（由 Domain.tune_template 推导）→ 前端按能力渲染页签，
  以后接数学建模分区时"调参"页签自动消失，不用改前端
- 新增 /api/shiti-list（结构化题目清单）与 /api/shiti-detail?file=（按精确文件名读题面）
- read_shiti 新增 file 参数（精确文件名优先），解决"多个年份同题号"的分析错年份问题
- /api/analyze 改为接收 file + label，任务里写明年份/批次并要求用 read_shiti(file=...) 精确定位
- 首页加 Cache-Control: no-store（避免改完前端浏览器仍用旧页面）

测试：tests/test_web.py 32 → 42 项，把信息架构锁进测试

电赛有 tune 能力而规划中分区没有）。三套共 89 项全过（全部离线）。
