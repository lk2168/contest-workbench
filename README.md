# 电赛 Agent（diansai-agent）

> 把一道**电子设计竞赛赛题**，变成一份**参赛队第二天早上就能照着干的作战方案**。
> 这不是"调一次 API 问一句"，而是一个**真正的 Agent**：它自己决定下一步查什么资料、调哪个工具，直到把报告写完。

**状态：v0.1（2026-09-29 首次跑通）**

---

## 实测结果（真实跑出来的，不是设想）

用 2026 年省级赛 **H 题《车载平衡滚球运动控制系统》** 跑完整流程：

| 指标 | 实测 |
|---|---|
| 自主步数 | 8 步（超步数上限 12） |
| 工具调用 | 4 类共 **24 次**（其中答疑检索 20 次，围绕"摆杆/钢球/循迹/图传/封箱/误差"等关键词） |
| 产出 | `out/H题-分析报告.md`（**18.8 KB**）+ 同名 **.docx（50.8 KB）** |
| 报告质量抽查 | 逐条拆解并标注分值（6/16/13/20/20/20/5/20）、从赛道几何**推出整圈 6.14 m** 与所需速度、3 个候选方案对比（舵机直推 / 步进丝杆 / 双闭环）、并抓到答疑里的硬约束（循迹**只能用红外光电模块**、摆杆 25 cm PPR 管、球位**必须用摄像头**、评分表赛前不公开） |

## 快速开始

```powershell
# 0) 依赖（本机已装 requests / PyYAML / pypdf / python-docx）
pip install -r requirements.txt

# 1) 自检：API Key 从哪来、真题库有什么题、模型名对不对（不花钱）
python cli.py --check

# 2) 空跑：只看提示词，不调用模型（0 成本，改提示词时用这个）
python cli.py analyze H --dry-run

# 3) 真跑：分析 H 题 → out/H题-分析报告.md + .docx
python cli.py analyze H

# 换更强的模型（更贵）
python cli.py analyze H --model deepseek-v4-pro
```

`analyze` 后面可以写**题号**（`H`）或**文件名片段**（`滚球`）。

## 它是怎么工作的（30 秒看懂 Agent）

```
         ┌──────────────── 循环（最多 N 步）────────────────┐
你 ──▶ messages ──▶ 模型 ──┬─▶ 直接回答 ──▶ 结束（写报告）   │
                          └─▶ 要调工具 ──▶ 执行 ──▶ 结果回灌 ┘
```

核心就是 `diansai_agent/loop.py` 里那 30 行：**模型只负责"决定下一步做什么"，程序负责"真的去做"，然后把结果喂回去**。这就是所有 Agent（Claude Code、Codex、DSH 自己）的共同骨架 —— 这里没有魔法。

它手上的 4 个工具（`diansai_agent/tools/`）：

| 工具 | 干什么 |
|---|---|
| `list_shiti` | 列出本地真题库（题号/标题/大小） |
| `read_shiti` | 读赛题正文（**已修掉 PDF"一字一行"的排版问题**） |
| `search_qa` | 在赛区官方《问题解答》里按关键词检索段落（指标口径、器材限制都在这） |
| `write_report` | 把报告写进 `out/`，并自动转一份 Word |

## 项目结构

```
diansai-agent/
├── cli.py                       # 命令行入口
├── diansai_agent/
│   ├── config.py                # Key/模型/路径（Key 来源：环境变量 → .env → DSH 凭据文件）
│   ├── llm.py                   # 一次模型调用（用 requests，不用 SDK）
│   ├── loop.py                  # ★ Agent Loop（心脏）
│   ├── prompts/
│   │   ├── system.md            # 角色与铁律（不许编造、必须标经验值、必须查答疑）
│   │   └── analyze.md           # 报告模板（8 个章节）
│   └── tools/
│       ├── __init__.py          # 工具注册表（JSON Schema + 执行）
│       ├── shiti.py             # 真题库：列出/读取/检索答疑
│       ├── report.py            # 写 md + 转 docx
│       └── md2docx.py           # 随仓库带走的 Markdown→Word 转换器
├── requirements.txt
├── .env.example                 # 复制成 .env 填 Key（不填也能跑，会自动读 DSH 凭据）
└── out/                         # 产物（不进版本控制）
```

真题库默认指向：`D:\deepseek-harness\gongzuoqu\diansai\真题库\2026省赛`（可用环境变量 `DIANSAI_KB` 覆盖）。

## 设计取舍（为什么这么做）

| 决定 | 理由 |
|---|---|
| **不用 LangChain 之类的框架** | 这个项目的目的是**学会 Agent 骨架**（也正好是 DeepSeek Harness 岗要的能力）；框架会把骨架藏起来。依赖越少越不容易坏 |
| **不用 openai SDK，直接 requests** | 让你能亲眼看到"一次调用到底发了什么、回了什么"，排错时这是决定性的 |
| **报告先生成 Markdown，再转 Word** | Markdown 好改好 diff，Word 好交付；转换器只有 400 行，随仓库走 |
| **Key 从 DSH 凭据文件兜底读取** | 本机不用再单独保管一份 Key；程序只读不打印 |
| **工具失败返回错误文本而不是抛异常** | 让模型看到错误、自己纠正（Agent 的常见自愈方式） |

## 已知限制（v0.1 不做的）

- 只做"**赛题 → 方案**"，还没有调参助手（v0.2）和自动评测（v0.3）
- 赛题里的**图片/示意图读不了**（PDF 只抽了文字），图上的尺寸标注需人工补
- 没有多轮交互（一次跑完），没有缓存（重复分析会重复花钱）
- 成本未按价格折算（只统计 token）

## Roadmap

| 版本 | 内容 | 验收标准 |
|---|---|---|
| **v0.2** | 调参助手：串口/CSV → 曲线 + 自动算**超调/上升时间/稳态误差** + PID 调整建议 | 用真实数据跑通，指标与手算一致 |
| **v0.3** | **评测**：10 条真题任务 → 自动打分（指标覆盖/器件齐全/时间线可行/风险识别）→ 回归报告 | 能看出"改提示词前后"分数变化 |
| v0.4 | DSH 技能薄壳（在 DSH 里直接喊）+ 可选 Web 界面 | 队友不装 Python 也能用 |

## 安全与费用

- **API Key 不写进仓库、不打印**：来源优先级 `环境变量` → `.env` → `~/.dsh/.credentials.yaml`
- `.gitignore` 已排除 `.env` / `out/` / `data/`
- 一次完整分析（H 题）约 8–12 次模型调用，用 `deepseek-flash` 属**几分钱**量级；跑完会打印 token 统计
- 想 0 成本调试：用 `--dry-run`
